# 墨小说漫画

小说、漫画、动画、游戏、AI、论坛资源分区导航。纯静态，无框架无依赖，可直接部署到 GitHub Pages。

## 文件

| 文件 | 说明 |
| --- | --- |
| `index.html` | 页面结构，卡片用 `<template>` 定义 |
| `styles.css` | 样式，深浅色主题走 CSS 变量 |
| `app.js` | 原生 JS，分区切换 + 搜索 + 翻页 + 点击统计 |
| `config.js` | 运行时配置，只有一项 `statsApi` |

| `sync_ai_section.py` | 从榜单站同步 AI 分区，管 id 前缀 `relay-` |

## 资源帮找 / 失效反馈

免责声明上方有「资源帮找 / 失效反馈」区块（默认收起），面板顶部两个标签切换：

**想要资源。** 访客匿名留言想看的作品，找到之后会加进站里。入站公告里也有一个跳转入口。

- 同一部作品重复提交会自动合并并加一票，不会刷出一堆重复条目
- 别人提过的作品可以点「▲」表示我也想看，票数高的排前面
- 三个状态页：待找 / 已找到 / 已关闭，已处理的会显示站长回复

**失效反馈。** 入口不在面板里，而是在**每张资源卡片内**：展开卡片，
底部有反馈按钮，点一下就报上去了。之所以不做成表单 ——
让用户手打资源名，收到的反馈常常对不上具体条目；按钮就在那张卡上，
带上去的 `item_id` 一定准确。

**所有条目都有这个按钮，不按「有没有链接」筛。** 链接能打开不代表内容还在：
网盘还活着但文件被删、解压码不对、资源只剩一半，都算拿不到。反过来，
压根没给链接的条目是最彻底的拿不到（按钮文案会换成「没有链接？点这里求补档」）。
该判断的是用户能不能拿到资源，那件事光看 `links` 字段判断不了，所以交给用户报。

- 同一条资源被多人反馈会合并成票数，票多的说明更多人撞上了
- 状态叫法换成「待补档 / 已补上 / 已关闭」，补好后会显示处理回复
- 点过的按钮会记在本机（`localStorage`），刷新后仍是「已反馈过」的完成态

两类共用一张表，靠 `kind` 区分；每日 5 条的提交上限**分别计算** ——
报了 5 条失效就不能再求资源，那样太苛刻。

- 不需要注册，也不记录身份 —— 和访问统计同一套指纹机制（IP+UA+日期的哈希，
  日期当盐，反推不出 IP）
- 单人每天每类最多提交 5 条，标题 60 字、说明 300 字

**这块依赖后端。** 接口不可用时整块隐藏，卡片里的反馈按钮也不会发请求 ——
显示一个提交后没反应的表单比没有表单更让人困惑。改状态和写回复要在 D1 里操作，
命令见 `worker/README.md`。

**后端没部署到位时会自动收起失效反馈。** 前端靠 `/api/requests` 返回的 summary
形状探测：分 kind 的是 `{want:{...},broken:{...}}`，老版是扁平的
`{open,found,closed}`。探测不到就隐藏类型标签、卡片里的反馈按钮，入站公告也换回
「有问题或资源失效，可在页面底部的反馈群里反馈」——否则公告会教用户去找一个
不存在的按钮。这样前端先上线、Worker 后部署的窗口期里，点了也不会在老后端存成
一条以资源名为标题的求助（那种脏数据得手工清）。

## 点击统计与热门排行

资源列表上方有「热门排行」面板（默认收起），搜索框旁边有排序下拉，可按
今日/本周/本月/本年/累计的点击数排。卡片标题旁会显示当前周期的点击次数，
0 次不显示。

计数只在点「打开」那类链接时增加 —— 展开卡片看详情不算点击。

**现在是全站模式：** 所有访客的点击汇总到同一个 Cloudflare D1 库，任何人从
任何设备打开都看到同一份排行榜，另外还能看到每天/周/月/年的访问人数（去重后
的人数，不是次数）。后端在 `worker/` 目录，地址配在 `config.js`，部署信息和
运维说明见 `worker/README.md`。

`config.js` 里配了两个接口地址，前端按顺序试第一个通的 —— 因为
`*.workers.dev` 在国内被墙，主入口用的是 `*.pages.dev`。两个地址读写同一个库。

接口全都不可达时会自动退回**本机模式** —— 点击只记在浏览器 localStorage 里，
排行榜只反映当前设备，访问人数显示为不可用。页面不会白屏。降级状态下点击
仍会补报到后端，所以网络抖动不会丢数据。本机模式下为了不让 localStorage
无限长大，只保留近 14 天 / 8 周 / 12 月 / 3 年的桶，累计那份永久保留。

改 `app.js` / `styles.css` / `config.js` 后记得把 `index.html` 里三处 `?v=`
版本号一起提，否则 Pages 的 10 分钟 CDN 缓存不会更新。

## AI 分区自动同步

AI 分区的中转站数据不要手改，它由中转站榜单站同步而来。数据源是
`../relay_board_site/data/resources.json`，改完那边跑一次：

```bash
cd mo_site
python sync_ai_section.py --dry-run   # 先看会改什么
python sync_ai_section.py             # 确认后写入
```

脚本会打印新增、移除、字段级变更明细。同步生成的条目 id 统一带 `relay-` 前缀，
脚本只覆盖这些；**其他分区，以及 AI 分区里 id 不带 `relay-` 前缀的手工条目，都不会被动。**
所以你想往 AI 分区加非中转站的资源，正常加就行，用别的 id 即可。

榜单站数据为空时脚本会中止，避免误清空整个分区。写入走临时文件再替换，
中途出错不会把 `items.json` 写坏。

## 成年 / 未成年模式

数据里带 `"adult": true` 的条目只在成年模式下显示。

- **默认未成年模式**，且刻意不做持久化 —— 每次打开页面都回到未成年模式，不记住上次选择
- 切到成年模式必须点确认弹窗（Esc 或点遮罩可取消）；关掉不需要确认
- 过滤在 `allowedItems()` 这一层统一处理，标签栏计数、小分区计数、搜索结果、顶部总数全部走它，搜索绕不过去
- 未成年模式下会提示「已隐藏 N 个成人向资源」

游戏区的标记规则在 `import_from_xlsx.py` 的 `GAME_SAFE_KEYWORDS` 里：白名单内（工具、加速器、资讯站等）不标记，**白名单之外的游戏条目一律标记为成人向**。宁可多标不可漏标，新增游戏资源时如果是正常内容，把关键词加进白名单。

`import_gal_xlsx.py` 导入的 Galgame 一律标记为成人向，没有白名单 —— 那个合集整体
就是成人向的。所以**默认未成年模式下游戏区只剩 2 条**，528 条 Galgame 要切成年模式才看得到。

## 回到顶部 / 到底部

右下角悬浮按钮，按滚动位置决定显示哪个方向：

- 页面可滚动高度不足 240px 时整组隐藏（教程区之类的短页面看不到）
- 距顶部 120px 内不显示「↑」，距底部 120px 内不显示「↓」——留余量避免临界处抖动
- 滚动事件用 `requestAnimationFrame` 节流，监听器加 `passive: true`
- 切分区/翻页后页面高度变化，`render()` 会回调重算显隐
- z-index 60，位于顶栏(20)之上、年龄弹窗(200)之下
- `prefers-reduced-motion` 下关掉平滑滚动与位移动效

## 翻页

默认 20 条/页，可切 10 / 20 / 30 / 50 / 100。翻页条含：共 N 条、每页条数、上下页、
页码（超过 7 页用省略号收起中间部分）、页数 > 3 时给「前往 N 页」跳转框。

一页装得下且用默认页长时整条隐藏，不占版面。

切换分区、小分区、搜索词、年龄模式都会重置到第 1 页 —— 否则会停在一个空页上看不到内容。
页码越界（比如切分区后条目变少）会自动收敛到最后一页。

## 下次表格更新了怎么办

**直接发完整表格就行，不用挑出新增部分。** 脚本按「全量重算 + 按 id 覆盖」工作：

```bash
python import_from_xlsx.py "路径\分享收录.xlsx" --dry-run   # 先看 diff
python import_from_xlsx.py "路径\分享收录.xlsx"
```

`--dry-run` 会打印「新增 N，移除 M，其余 K 条按最新表格刷新」，并列出新增/移除的条目名。

规则：

- 导入条目 id 形如 `xlsx-<分区>-<序号>`，重跑时同 id 覆盖，**不会重复添加**
- 表格里删掉的条目，重跑后也会从站点移除
- 表格里改了链接或提取码，重跑后跟着更新
- **AI 分区（`relay-` 前缀）和手工添加的条目完全不受影响**

已验证幂等：同一份表格连跑两次，116 条逐字段完全一致。

### 一个坑：别在导入后手改数据

序号是按行顺序生成的，表格中间插入一行会让后面所有条目的 id 顺移一位。所以
**手改 `items.json` 里的导入条目没有意义，下次重跑会被覆盖回去**。

要修正归类或名称，改脚本顶部这两张表：

- `RECLASSIFY` —— 按标题关键词强制归到某个分区（如「可露希尔小卖部」归到工具区）
- `RENAME_BY_URL` —— 按 URL 覆盖写错的标题（依据是实际页面 `<title>`）

这样修正会在每次导入时自动套用，不会丢。

## 多网盘源

同一资源常同时给百度/UC/夸克多个源，数据里用 `links` 数组表示：

```json
{
  "url": "https://drive.uc.cn/s/xxx",
  "password": "abcd",
  "links": [
    { "name": "UC 网盘", "url": "https://drive.uc.cn/s/xxx", "password": "" },
    { "name": "百度网盘", "url": "https://pan.baidu.com/s/yyy", "password": "abcd" },
    { "name": "夸克网盘", "url": "https://pan.quark.cn/s/zzz", "password": "", "label": "体验版" }
  ]
}
```

`url` / `password` 保留主源，供不读 `links` 的场景兜底。前端会给每个源渲染一个按钮，
各源的提取码分别显示在自己按钮旁边——因为不同网盘的提取码往往不一样，共用一个会给错。

只有单个源时不需要写 `links`，前端会用 `url` 自动兜底。

## xlsx 导入的解析坑

**空格子是自闭合标签。** Excel 把空单元格写成 `<c r="D5" s="6" t="s"/>`。
如果用 `<c ...>(.*?)</c>` 匹配，正则会跨过自闭合标签去找下一个 `</c>`，
把后面格子的值算到前一列上，**整行列错位**。`parse_sheet()` 里必须显式区分两种形式：

```python
r'<c r="([A-Z]+)(\d+)"([^>]*?)(?:/>|>(.*?)</c>)'
```

我第一版没处理这个，导致工具区链接全体错位一格（endgear.top 配到了别的标题上）。
修好解析后，表格其实就是规整的「A 列标题、B 列起是链接」，不需要任何偏移补偿。

改这块逻辑后务必抽查几行的列归属，再抓 URL 的 `<title>` 跟条目名对照。

## 怎么加资源

编辑 `data/items.json`，在 `items` 数组里加一项：

```json
{
  "id": "唯一标识",
  "name": "资源名称",
  "section": "novel",
  "description": "一两句简介，卡片上最多显示两行",
  "url": "https://example.com/",
  "tags": ["标签1", "标签2"],
  "kind": "网站",
  "need_login": false,
  "update_info": "每日更新",
  "note": "备注，留空则不显示"
}
```

`section` 取值：`novel` 小说、`manga` 漫画、`anime` 动画、`game` 游戏、`music` 音乐、`tool` 工具、`ai` AI、`forum` 论坛、`guide` 教程/问题、`collection` 收录/杂类。

**不确定归哪个分区就填 `collection`。** 那个分区叫「收录 / 杂类」，就是收这类东西的：
网盘合集入口、说明文档，以及一时分不清类别的资源。想清楚了再改 `section` 挪走即可。

`section` 填错或留空也会落到 `collection`（见 `app.js` 的 `FALLBACK_SECTION`），
卡片不会丢。以前的兜底是小说区 —— 那会把杂七杂八的东西混进小说里，所以改了。

**手工添加的条目 id 请用 `manual-` 前缀**，这样 xlsx 重跑导入时不会被清掉（已验证）。

`tags` 最多显示 6 个，`icon` 可选，不填则用分区默认图标。

### 小分区（subsection）

小说、漫画、动画、游戏四个分区有小分区，数据里用 `subsection` 指定：

| 分区 | 可选 `subsection` |
| --- | --- |
| `novel` 小说 | `site` 网站、`app` 软件、`download` 下载、`kr` 韩轻、`jp` 日轻 |
| `manga` 漫画 | `site` 网站、`app` 软件、`wechat` 公众号、`download` 下载、`kr` 韩漫、`jp` 日漫 |
| `anime` 动画 | `site` 网站、`app` 软件 |
| `game` 游戏 | `site` 网站、`app` 软件、`gal` Galgame |

`site` 放在线站点，`app` 放客户端/APP，其余按语种分。不填 `subsection` 的条目仍会
出现在该分区的「全部」里，只是点具体小分区时看不到它 —— 所以新加条目建议都填上。

写了分区没有的 `subsection` 会被当成没填（`normalize()` 里按 `subs` 白名单校验），
不会丢卡片。小分区计数为 0 的标签仍然显示，方便看出这一格还没收东西。

### 一份资源属于多个分区（also_in）

网盘包里既有小说又有漫画的情况很常见。只挂在小说区的话，逛漫画区的人根本
看不见它，所以这类条目用 `also_in` 补上附加分区：

```json
{
  "id": "manual-novel-dl-10",
  "name": "厌学魔法师想毕业（小说 + 漫画）",
  "section": "novel",
  "subsection": "download",
  "also_in": [{ "section": "manga", "subsection": "download" }]
}
```

`section` 仍是主分区，`also_in` 是数组，可以列多个（书兔那三条同时进
小说 / 漫画 / 动画）。效果：

- 在列出的每个分区、每个小分区里都能被搜到，小分区计数也算它一份
- 卡片上的分区标签跟着**当前所在分区**走 —— 在小说区显示「韩轻」，
  在漫画区显示「韩漫」，旁边再加一个虚线的「也在 X」告诉你这份里还有别的
- **仍然是一条数据。** 点击数、失效反馈都绑在 `id` 上，拆成两条会把统计
  和反馈劈成两半，「全部」分区里也会出现两张一样的卡

`import_from_xlsx.py` 的 `add_cross_sections()` 会自动给「XX漫画小说」这类
标题补上 `also_in`（小说↔漫画双向），所以重跑导入不会把它冲掉。手工条目
（`manual-*` 前缀）不受导入影响，直接在 `items.json` 里写。

## 论坛区

`forum` 分区收录可以逛的社区/论坛。目前一条：

- **LINUX SB（烧饼社区）** `https://linux.sb/` —— AI 技术交流论坛，版块有技术交流、
  资源分享、福利放送、求助问答等。中转站免费额度、签到脚本这类东西多是从这里流出的。
  实测**不登录能看帖**（版块页、帖子正文都是 200），但**评论区要登录才显示**
  （页面上写「共 N 条评论，登录后可见」）。注册只要邮箱验证码 + 一道算术人机验证，
  没有邀请码门槛；站内是积分体系，上传之类的权限要攒积分。

条目 id 用 `manual-forum-N`，不受 xlsx 导入和 AI 同步脚本影响。

## 地区限制站点怎么收录（书兔导航的坑）

小说区的 `manual-novel-1`「书兔导航」是韩国站 뉴토끼 的地址发布页，收录时踩了两层墙，
下次遇到同类站点直接照这个套路来，别重新试一遍：
- **导航页本身国内打不通。** `telegra.ph` 直连超时，挂本机代理（7890 / 1080）也是
  TLS 握手失败退出码 35 —— 那两个代理连 Google 是 204 通的，所以是 telegra.ph 这个域
  被单独干掉了，不是代理坏了。最后靠 `https://r.jina.ai/<url>` 走代理把正文取出来。
- **页面里给的站点做了韩国 IP 限制。** Cloudflare 直接回 403，`Block reason: KR_ONLY`
  （`only KR is allowed, detected country is CN`）。而且是**间歇性**的：首页和
  `/novel`、`/manhwa/updates` 多数 200，作品详情页时通时不通（同一个 URL 重试两次
  一个稳定 200 一个稳定 403），`toki31.com` 一直被拦。
- 所以条目里用 `links` 把导航页 + 几个实际地址一起列出来，`label` 标明哪个能用、
  哪个要绕过；`note` 里写清 403 现象和导航页教的 DNS 绕过办法（1.1.1.1 / Unicorn HTTPS）。
  只放导航页一个链接的话，访客点进去只会看到超时白屏。

**注意站内有 🔞 成人分区和赌博性质的积分小游戏**，但条目本身指向的是小说导航，
和游戏区那种整包成人内容不是一回事，所以没标 `adult: true`，改为在 `note` 里提醒。

### 뉴토끼 三条条目的分工

小说区 `novel/site` 下这三条是同一个站的不同入口，别当成重复收录：

| id | 条目 | 国内直连实测 |
| --- | --- | --- |
| `manual-novel-1` | 书兔导航（地址发布页） | 打不通（telegra.ph 被墙） |
| `manual-novel-2` | 新书兔 toki31 | 首页连试三次全 403 |
| `manual-novel-3` | 旧书兔 newtoki1 | 首页连试三次全 200，内页 403 |

域名会换，所以导航页那条留着；但导航页自己在国内打不开，单独收录新旧域名才有实际用处。
**`note` 里的可达性结论都标了「实测」并写了重试次数** —— 这类站随时可能变，
下次要改先自己重测，别照抄。

`note` 和 `description` 走 `textContent` 渲染，写 `**加粗**` 只会原样显示星号，别写 Markdown。

## Galgame 合集导入（第二套导入脚本）

游戏区的 `gal` 小分区由 `import_gal_xlsx.py` 从「gal 合集主」表格生成，
和 `import_from_xlsx.py` **完全独立**：

| | 管的 id 前缀 | 数据源 |
| --- | --- | --- |
| `import_from_xlsx.py` | `xlsx-` | 分享收录.xlsx |
| `import_gal_xlsx.py` | `gal-` | gal合集主 - 录入.xlsx |

各扫各的前缀，重跑互不清空（已验证：跑完 gal 导入后，旧脚本 dry-run 仍报
「新增 0，移除 0，非导入条目 555 条保留不动」）。

```bash
python import_gal_xlsx.py "D:\game\...\gal合集主（先把我下载下来再看） - 录入.xlsx" --dry-run
python import_gal_xlsx.py "D:\game\...\gal合集主（先把我下载下来再看） - 录入.xlsx"
```

**必须用 openpyxl 读超链接。** 这张表的网盘地址是 Excel 超链接对象，单元格文字
只是「夸克网盘分享」这类说明词。`import_from_xlsx.py` 靠正则扫单元格文本，
对这张表**一条都扫不出来** —— 所以是两个脚本而不是给旧脚本加个分支。

表格结构是**三块内容横向并排**，不是一张连续的表：

| 块 | 列 | 行 | 说明 |
| --- | --- | --- | --- |
| 1 | A=名字 B=链接 C=解压码 | 3–360 | 主体，名字带 `pc/安卓/kr` 平台前缀 |
| 2 | D=名字 E=链接 F=解压码 | 9–41 | 新增区，多数只有名字没链接 |
| 3 | A=编号 B=名字 G=平台 H=链接 | 366–535 | 按社团分组，组头是「XX社合集」 |

几个已经踩过的坑，改脚本前先看：

- **id 用名字的哈希，不用行号。** 表格插删行、重排序时行号会变，id 跟着变就等于
  「删一条 + 加一条」，点击统计会串到别的作品上。改名字仍会被当成换了一条。
- **平台前缀只在开头识别。** 作品名里也有拉丁字母，从中间乱切会截断名字。
  表里还有把 `ios` 打成 `ips` 的，以及 `安卓使用电脑模拟器` 这种长写法，都在
  `PLATFORM_TOKENS` 里兜住了。
- **名字里混着 nbsp(`\xa0`) 和全角空格**，不统一压掉会留下 `'\xa0 魔女的夜宴'`
  这种前导空白，走 `norm_space()`。
- **结尾的 `-` 不能剥。**「夏日口袋 -REFLECTION BLUE-」那个尾巴是标题的一部分。
- **解压码不是网盘提取码。** C/F 列的 `0721`/`bbxz` 是压缩包密码，卡片上
  `password` 字段显示为「提取码」，混进去会让人拿它去填网盘密码框。所以解压码写
  进 `note`，`password` 只放链接里自带的 `?pwd=`。
- **同一网盘出现多次要加序号。** 有的作品给了两个迅雷链接，不加 `label` 的话
  详情页会出现两个一模一样的「迅雷网盘」按钮。

### 数据规模与成人向标记

导入 532 条（单品 488 + 打包卷 20 + 社团合集 20 + 工具 4）。**Galgame 全部标
`adult: true`** —— 这个合集整体定位就是成人向，漏标的后果比多标严重得多。
代价是**默认（未成年模式）看不到它们**，要点右上角切成年模式并确认年龄。
工具那 4 条（解压教程/软件/模拟器）归到工具区且不标记，本身没有内容。

`items.json` 因此从 75KB 涨到 380KB，gzip 后 40KB，加载没有问题。

## 加新分区

改 `app.js` 顶部的 `SECTIONS` 数组，加一项 `{ id, label, icon }`，然后数据里 `section` 用这个 id。标签栏和计数会自动出来，不用改别处。

加小分区同理，在那一项里加 `subs: [{ id, label }]`。`subs` 存在时小分区栏才显示，
所以给分区加第一个小分区就等于让它多出一行标签栏。
